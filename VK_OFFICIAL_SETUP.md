# Автоматический сбор публичных публикаций VK: 159 профилей ЮАО

Проект использует официальный метод **VK API `wall.get`**, по одному запросу на каждый профиль из `deputies.json` (159 уникальных хэндлов, 16 районов). Мониторинг охватывает только доступные из официального API публичные записи. Наличие профиля в историческом справочнике **не доказывает**, что он принадлежит действующему депутату или что страница остаётся доступной.

## Безопасный порядок включения

1. **Проверка без токена.** В GitHub откройте **Actions → Collect public VK posts (official API; 159 profiles) → Run workflow**, выберите ветку обновления и режим `test`. Запустятся только локальные тесты с подставными ответами: **0 запросов к VK, 0 изменений файлов**. То же автоматически происходит при обновлении кода сборщика.
2. **Настроить отдельный секрет.** Получите VK API access token, имеющий право читать доступные публичные стены через `wall.get`. Добавьте его в **Settings → Secrets and variables → Actions → New repository secret** под именем **`VK_TOKEN`**. Не присылайте токен в чат и не помещайте его в HTML, GitHub Issues, коммиты или ссылки. GigaChat API ключ для VK API не подходит.
3. **Пилот.** В Actions выберите режим `pilot`. Скрипт сделает **не более пяти запросов `wall.get`** (с повторами только при временных сбоях) по первым пяти профилям, отобразит агрегированный отчёт, но **не запишет и не закоммитит** полученные данные. Доступ к некоторым страницам может быть ограничен VK API.
4. **Первый полный сбор.** После проверки логов запустите workflow **на ветке main**: режим `full`, поле `confirm_full` = `YES`. Он проверит все 159 профилей, сохранив существующие записи и метаданные. Настройка непроверенных токенов/прав может приводить к ошибкам или отсутствию данных; скрипт не подменяет их нулями.
5. **Ежедневное расписание.** После успешного полного сбора добавьте в **Settings → Secrets and variables → Actions → Variables** переменную **`VK_COLLECTION_ENABLED`** со значением `true`. Только тогда будет разрешён ежедневный запуск (cron `47 6 * * *`, UTC). До этого расписание **не делает сетевых запросов к VK**. Переменная `false` или её удаление немедленно отключит будущие плановые сборы.

## Гарантии сохранения данных

- Источник: `deputies.json` — 159 профилей; отправляются запросы только к публичному VK API, без обхода закрытых страниц.
- Каждый запуск получает до **100 последних доступных публикаций на профиль**, а не всю историю ВКонтакте. Дальнейшие ежедневные запуски добавляют новые записи.
- Ключ уникальности — пара `profile + url`. При совпадении обновляются доступные метрики, но пустой новый текст **не уничтожает** ранее сохранённый. Старые записи Apify/CSV, служебные поля и `monitored_profiles` сохраняются. Признак репоста берётся из метаданных поста, не из числа репостов.
- Ошибки доступа и пустые ответы записываются раздельно. Пустой результат не означает отсутствия деятельности депутата. При ошибке авторизации сбор останавливается.
- `vk-posts.json` содержит историю и данные для ИИ. `monitor-status.json` — результаты по профилям. Независимая HTTP-проверка страниц теперь пишет отдельный `profile-reachability.json`, чтобы не затереть статусы VK API.
- Запись JSON выполняется через временный файл и атомарную замену; `git push` выполняется без принудительной перезаписи истории. При конфликте коммитов действие завершится ошибкой, а не затрёт удалённые данные.
- `GigaChat` уже следит за изменениями `vk-posts.json` и постепенно классифицирует полученные тексты по 14 категориям.

## Ограничения

- Доступ к `wall.get`, количество запросов, права токена и ограничения публичных страниц определяет ВКонтакте. Доступность всех 159 профилей **не гарантируется**.
- Скрипт не проходит авторизацию за депутата, не читает закрытые данные, не утверждает личную принадлежность профиля, не подтверждает факт проведённых мероприятий.
- Существующие импортированные тексты не удаляются, но их достоверность зависит от первоначального источника; это не независимая верификация.
- Пилот делает реальные обращения к VK API (только при наличии ключа), но не меняет данные в репозитории. Режим `test` полностью офлайн.
