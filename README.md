# Цифровой профиль депутата

Мобильная статическая панель для восьми пилотных публичных VK-профилей.

## GitHub Pages

В репозитории откройте **Settings → Pages → Build and deployment**, выберите **Deploy from a branch**, ветку **main**, папку **/(root)**, нажмите **Save**. Адрес после публикации: https://legion68910102-dotcom.github.io/deputy-monitor/

## Оформление административного округа

В шапке версии ЮАО вместо повторяющихся навигационных плиток отображается **гербовая эмблема Южного административного округа Москвы**. Ниже остаются оригинальные раскрывающиеся разделы приложения.

- Источник гербовой эмблемы: [Wikimedia Commons, UAO district of Moscow coa.png](https://commons.wikimedia.org/wiki/File:UAO_district_of_Moscow_coa.png). На странице файла указан статус государственного символа РФ (PD-RU-exempt). Изображение выводится без изменений с Wikimedia; для полностью автономного хостинга его можно позднее положить в `assets/okrugs/`.
- Настройка оформления: `okrug-branding-v132.js`. По умолчанию применяется ЮАО, **16 районов**, сокращение и изображение ЮАО.
- При подключении набора данных другого округа его загрузчик должен **до подключения скрипта оформления** задать `window.deputyMonitorOkrugConfig = {code, abbreviation, fullName, districtsCount, emblemUrl}`, где `emblemUrl` — надёжная `https://` ссылка или `./assets/okrugs/name.svg` / `.png`. Скрипт заменяет название, описание и изображение при загрузке, без правки основного HTML.
- **Это только архитектурная подготовка.** Сейчас данные приложения по-прежнему относятся к ЮАО; дополнительных округов, переключателя и независимых клиентских баз ещё нет. Подменять герб без соответствующего набора данных другого округа нельзя.

## Гербы районов и оформление списков

В «Профилях депутатов» перед названием каждого из **16 районов ЮАО** показывается его герб; заголовки районных вкладок имеют светло-серый фон. Изображения загружаются как маленькие миниатюры (120 пикселей, допустимый Wikimedia стандарт) из [Wikimedia Commons](https://commons.wikimedia.org/wiki/Category:Coats_of_arms_of_municipal_divisions_of_Moscow), сопоставление районов и файлов хранится в `district-coats-uao-v133.js`.

- Если внешний сервер изображений недоступен, картинка скрывается, но название района и список депутатов остаются доступными.
- Геральдические изображения не заменяют проверку актуальности состава депутатов.
- При дальнейшем подключении других округов потребуется собственный реестр гербов соответствующих районов.

## Права доступа и локальные исправления

Отдельная вкладка «Личное пространство» **удалена**: она не соответствует планируемой модели единой платформы с разграничением прав по округам. Общие публикации VK/GigaChat по-прежнему обновляются централизованно. Посетители не получают права изменять общий репозиторий или базу.

До реализации серверной авторизации и ролей некоторые существующие операции (например, ручной импорт CSV, фото и сведения в карточках) сохраняются в конкретном браузере. Отдельная кнопка **«🔁 Это репост (только у меня)»** остаётся внутри «🧠 Анализ деятельности по текстам», чтобы исправлять неполные метаданные старых публикаций, не изменяя данные других пользователей.

Для будущей платформы предусмотрены роли: администратор района — только просмотр; администратор округа — управление записями своего округа. Сейчас эти серверные роли **ещё не реализованы**.

**Важно:** публичный исходный код нельзя сделать технически некопируемым. Любой человек может изучить полученные браузером файлы, но не может обновить оригинальный репозиторий без прав на запись. Права на оригинальные элементы кода и дизайна сохраняются за соответствующим правообладателем; сторонние публикации и фотографии принадлежат своим авторам. См. [COPYRIGHT_NOTICE.md](COPYRIGHT_NOTICE.md).

## Определение репостов VK

Репосты распознаются по **метаданным самой публикации**: официальный VK API `copy_history`, тип `copy`, подтверждённый источник первоначальной записи. Количество репостов под записью и просто упоминание имени другого человека **не** являются доказательством репоста. При сборе VK API сохраняется ссылка на оригинал; если репост не сопровождается собственным текстом, используется текст исходного автора с отметкой о происхождении.

Ранее импортированные публикации могут не содержать этих метаданных. В разделе **«🧠 Анализ деятельности по текстам»** пользователь может открыть публикацию и нажать **«🔁 Это репост (только у меня)»**. Исправление немедленно отражается в его анализе, но **не изменяет** общую базу и записи других пользователей. Повторная проверка метаданных через официальный VK API требует настроенного `VK_TOKEN` и успешного сбора. Репост может одновременно быть «Публикацией-анонсом» — но это не доказательство участия депутата.

## Данные

Для публичных публикаций ВКонтакте подготовлен официальный сбор через VK API: тест без сети, пробная проверка пяти профилей без записи и полный обход всех 159 профилей. **Серверный опрос VK запланирован дважды в сутки**. Запуск больше не скрывается за переменной `VK_COLLECTION_ENABLED`: при отсутствии `VK_TOKEN` workflow завершится заметной ошибкой вместо ложного успеха. Для реального сбора нужен секрет `VK_TOKEN` с разрешением на `wall.get`. При каждом заходе на сайт загружается актуальная опубликованная база; это не новый запрос к VK API. Виджет вверху показывает дату последнего настоящего опроса, доступность источника и ошибки. Подробности — [VK_OFFICIAL_SETUP.md](VK_OFFICIAL_SETUP.md). Старые публикации Apify/CSV при сборе сохраняются. Локальный импорт CSV по-прежнему хранится только в браузере (localStorage) и не синхронизируется между устройствами. Пустые метрики не заменяются нулями. Не добавляйте API-токены, пароли или закрытые персональные сведения в публичный репозиторий.

## Ограничения

Это пилотная версия без серверной авторизации пользователей; запланированный сбор VK работает только при наличии действующего VK_TOKEN. GitHub Actions может запускать серверные задачи, но GitHub Pages сам по себе не собирает VK при открытии страницы. Оценка работы депутата не должна строиться только на показателях соцсетей.

## Даты рождения — все 16 районов ЮАО

Общий справочник `deputies.json` содержит 159 профилей, поля `birth_date` (ISO YYYY-MM-DD), `birth_source` (ссылка), `birth_status` и `birth_last_checked`. По состоянию на 21.11.2026 дата указана в 21 профиле, отсутствует в 138. Ссылка на источник **не равна независимой проверке**. Исторический состав советов также требует актуализации.

Проверка **сразу всех** районов: `python3 scripts/audit_birth_dates.py`. Скрипт обновляет `reports/birth-date-audit.csv` (каждый депутат, статус, источник, рассчитанный возраст) и `reports/birth-date-summary.json` (покрытие по районам). Возраст вычисляется на дату запуска; при неизвестной дате рождения не угадывается. Для публикации новых дат требуется сверить биографию с первоисточником и внести подтверждённые сведения в справочник и интерфейс.

## Состояние карточек ЮАО (проверено 22.11.2026)

Справочник `deputies.json` содержит **159 записей** по 16 районам. Это исторический перечень: действующие полномочия и состав советов требуют отдельной проверки.

- **Места работы:** в 155 записях есть `workplace` и `workplace_source`, все 155 имеют статус `source_linked_review_pending`. Это данные со ссылкой на источник, **не подтверждение актуального места работы**. В четырёх записях поле отсутствует: Виноградова Елена Геннадьевна (Бирюлёво Западное), Анисимова Светлана Геннадьевна (Зябликово), Донская Татьяна Викторовна (Орехово-Борисово Южное), Коношенко Богдан Александрович (Чертаново Центральное).
- **Даты рождения:** поле `birth_date` заполнено в 159 записях, но только 3 имеют статус `cross_checked`; остальные 156 — `source_linked_review_pending`. Не следует трактовать заполненное поле как независимо проверенное.
- **Аватарки ВК:** `vk-avatars.json` содержит 159 статусов `needs_token`, подтверждённых фотографий через VK API пока нет. Не подставляйте фотографии других людей или неподтверждённые изображения.
- **VK-мониторинг:** наличие приложения VK ID и его сервисного ключа не означает разрешённый доступ к публикациям всех депутатов. Ключи нельзя публиковать в репозитории или клиентском JavaScript; при появлении разрешённого доступа используйте только секреты GitHub Actions или серверной среды.

**Приоритет:** проверить четыре отсутствующих места работы по первоисточникам, сверить актуальность остальных сведений, затем заполнить фотографии из подтверждённых открытых источников и проверить мобильное отображение. Отсутствующие данные должны оставаться явно обозначенными как неизвестные.
